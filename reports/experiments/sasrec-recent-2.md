# SASRec с двумя последними событиями: 256 и 1 000 пользователей

8 ноября 2026. Оба контроля обучены локально на Apple M3 Pro, MPS, FP32, CPU fallback отключён. Проверяется [заранее предложенный контроль](../../notes/sasrec-next-repeat-experiment.md) после [аудита повторов](sasrec-joint-repeat-audit.md).

На общей когорте короткая история повысила NDCG 256 на **28.2%**, но снизила Recall на **8.8%**. У 1k рост NDCG составил **8.8%**, его парный 95% интервал включает ноль; Recall снизился на **18.7%**. При двух событиях 1k уступает 256 на **35.0% NDCG** и **15.9% Recall**. На отдельном полном native test 1k NDCG выросла на 11.6%, Recall снизился на 18.7%.

Повторы улучшились у обеих моделей, но полного улучшения по двум метрикам нет. Отставание 1k сохранилось и при одинаковом коротком контексте. Следовательно, контроль не подтверждает сокращение истории как исправление baseline и не позволяет объяснить всю исходную потерю одной длиной контекста.

## Единственное изменение

`context_keep: 2` маскирует ранние токены исходных prefixes во время train, validation и test. Тензор сохраняет длину **50**, последние токены остаются в позициях 48 и 49. Данные, targets, словарь, sampler, 16 negatives, joint-mean BCE, seed 42, batch 256, Adam 0.001 с betas (0.9, 0.98), clipping 5, dropout 0.2 и архитектура сохранены. Initial state каждого размера побитово совпал с соответствующим 50-контролем; проверены SHA-256 всех семи файлов каждого набора. Входная маска не использует targets и не потребляет RNG.

[Конфиг 256](../../configs/experiments/sasrec-256-recent-2.json), [конфиг 1k](../../configs/experiments/sasrec-1k-recent-2.json), [проверки](sasrec-recent-2/verification.json). ID-эмбеддинги обучаемые. Число train-примеров: 739 571 и 2 799 860; validation: 29 313 и 100 809. Маска не уменьшает физическую длину тензора; отдельный benchmark ускорения не выполнялся.

## Адаптация при обучении против простой inference-маски

Для каждого размера — собственная полная validation и native-каталог. Исходные selected-checkpoint метрики воспроизведены. 1k-инференс-контроль переиспользует проверенные ranks из предыдущего аудита; два режима 256 оценены локально без переобучения.

| Модель и вход | Validation NDCG@10 | Validation Recall@100 |
| --- | ---: | ---: |
| 256: обучен 50, вход 50 | 0.043825 | 0.290213 |
| 256: обучен 50, вход 2 | 0.043111 | 0.221574 |
| 256: обучен 2, вход 2 | 0.055054 | 0.258964 |
| 1k: обучен 50, вход 50 | 0.045040 | 0.259560 |
| 1k: обучен 50, вход 2 | 0.053542 | 0.207055 |
| 1k: обучен 2, вход 2 | 0.049831 | 0.214098 |

Заранее заданный критерий улучшения: обе общие validation-метрики не ниже 50-контроля, хотя бы одна строго выше. Для 256 применён тот же критерий относительно своего 50-контроля.

- 256: критерий по двум общим validation-метрикам **не выполнен**.
- 1k: критерий по двум общим validation-метрикам **не выполнен**.

Адаптация к короткому входу различается. У 256 обучение на двух событиях улучшает обе validation-метрики относительно простого маскирования прежнего checkpoint. У 1k адаптация немного возвращает Recall (0.207055 → 0.214098), но снижает NDCG относительно inference-маски (0.053542 → 0.049831). Поэтому наблюдавшийся в аудите эффект маски нельзя переносить на результат нового обучения без проверки.

## Проверки и ограничения

29 тестов прошли, включая BCE, CPU/MPS и маскирование train/validation с сохранением ширины и последних позиций. Совпали initial state, данные и параметры внутри каждого размера; checkpoints старых моделей не изменились. Выбор эпохи соответствует максимуму validation и patience 2. Проверены targets/users/catalog при сравнении, SHA-256 исходных и замаскированных reference histories, воспроизведение selected validation. Старые конфиги сохраняют прежний полный контекст по умолчанию.

На 32 выбранных событиях (16 повторов и 16 неповторов) для каждого нового native checkpoint и отдельно для shared-оценки 1k проверен CPU scoring. У 256 один ранг отличается от MPS на 1, метрики совпадают; у 1k все выбранные ранги совпадают. Веса конечны. [CPU-check](sasrec-recent-2/cpu-check.json).

Один seed не оценивает разброс переобучения; bootstrap-интервалы не включают эту вариативность. MPS-training не гарантирует побитовую повторяемость. Test уже использовался в исследовательских сравнениях. Между 256 и 1k различаются train/validation, словарь и размер item-таблицы. При разном числе эпох сравнивается один протокол early stopping, а не равные compute budgets. Времена отдельных запусков не являются повторным benchmark.
