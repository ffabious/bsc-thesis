Jev: что полезно для диплома

6 препринтов + 1 программный ресурс. Все шесть статей доступны в arXiv HTML.

СтатьиЭкспериментыРесурсы
Главная связь с пропозалом: общий контекст для дешёвого скоринга и небольшой контроллер, который решает, стоит ли тратить дополнительные вычисления.

TypeSafe описывает Jev как модель структурированных вероятностных решений: Choice, Score и Noul. Общий state подаётся вместе с вопросами. Полный алгоритм обучения закрытого Jev не раскрыт; RLCD в материалах компании — название её метода. Первичный материал TypeSafe.

Гарантия формы ответа не гарантирует верность решения. Для диплома важны качество, calibration и полная стоимость на своих данных.

Шесть работ по типам методов

P069 · Рекомендации · читать первым

Jev-Rec

Decision-Oriented Recommendation Reranking: An Empirical Study of Jev

Jev ранжирует кандидатов по вероятностям Choice, используя 10 последних взаимодействий и текстовые описания товаров. Проверка на трёх доменах Amazon, K=20–200.

Target искусственно включён в кандидаты; оценены только пользователи с target в SASRec top-200. Hosted API и локальные GPU не сопоставлены по hardware.

P071 · KV reuse · читать первым

Visual Jev

Visual Jev: Accurate and Efficient Decisions from Shared Visual Context

Общий визуальный префикс кодируется один раз, независимые вопросы исполняются батчем. Факторный эксперимент отделяет reuse от batching.

Визуальные задачи, не RecSys. Выигрыш рассчитан на совместно доступные вопросы; амортизированное время не равно задержке запроса. Mixed precision меняет отдельные ответы.

P073 · Контроллер памяти · смежная область

Jev-Mem

Jev-Mem: System-One-Controlled Agentic Memory for Efficient AI Agents

Контроллер управляет записью и поиском агентной памяти: маршрутизацией, бюджетом графа, оценкой кандидатов и остановкой по достаточности и ожидаемой пользе поиска.

Agentic memory и retrieval на LoCoMo; не проверяет freshness user embeddings или refresh policies на Yambda. Применение в дипломе — гипотеза.

P072 · Открытый decision readout · смежная область

AnyJev

AnyJev Technical Report

Открытая LLM возвращает распределение по option tokens без генерации. Label prior и cyclic rotations уменьшают смещение; ранняя остановка сокращает число prefills.

Несколько rotations требуют нескольких prefills. Сертификат ограничивает disagreement с полным вариантом, не ошибку относительно истины. KV блока после state нельзя переносить между разными state.

P070 · Независимая оценка

Jev-Benchmark

Evaluating and Benchmarking the System One Model Jev

Независимая проверка jev-1.13.0 на 37 наборах. Choice, Score и Noul имеют разные свойства; хорошее ранжирование не гарантирует подходящий бинарный порог.

Это NLP benchmark, не музыкальная рекомендация. Закрытые training data не позволяют исключить contamination; промпты и baseline readout влияют на результат.

P074 · Обучение вероятностей · расширение

OpenJev-RLCD

OpenJev-RLCD: A Working RLCD Implementation

Открытая реализация обучает вероятностный readout и затем reasoning, используя proper score для каждого rationale. Анализирует calibration и selective prediction.

Независимая реализация, не раскрытие закрытого алгоритма TypeSafe. Генерирует rationale; результат не доказывает одношаговый быстрый inference коммерческого Jev.

Что проверить в дипломе

Ниже — наши предложения. Эти эксперименты на Yambda в найденных статьях не выполнены.

ПроверкаСравнениеЧто измерить
Reuse × batchingЧетыре режима: полное вычисление; только reuse; только batch; reuse + batch. Один фиксированный user-prefix, одинаковые веса и позиции.Ошибка scores, совпадение top-k, время всей группы, throughput, peak memory. Разделить амортизацию и request latency.

Перестановка кандидатовЕсли используется текстовый decision readout: несколько детерминированных порядков и optional rotation averaging.Изменение ranking и дополнительная стоимость prefills; пороги на validation.
Semantic rerankingДополнительная ветвь при наличии содержательных item metadata. Фиксированный retriever; реальные top-K кандидаты.End-to-end quality на всех пользователях, retrieval coverage, conditional rerank quality, локальное время или API latency отдельными величинами.

Refresh, если ожидаемый выигрыш > λ × стоимость обновления.

λ подбирается на validation под вычислительный бюджет. Вероятность «refresh поможет» сама по себе не учитывает величину выигрыша и цену. Начать с простой обучаемой регрессии; внешний Jev для этого не обязателен.

Формулировка вклада: проверить предсказание пользы обновления пользовательского состояния в chronological replay на Yambda. Jev-Mem уже использует ожидаемую пользу для продолжения поиска памяти; поэтому общая идея benefit-based compute имеет предшественников. Его результаты не подтверждают готовую refresh policy для рекомендателя.

Практический ресурс

JevEmbed — инструменты обучения и локального исполнения Choice/Score/Noul на embedding models. Программный ресурс сохранён отдельно от научных статей; в счётчик статей не включён. Использовать как возможный baseline после проверки собственного benchmark.
