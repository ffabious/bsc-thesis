# Увеличенные SASRec на 256 и 1 000 пользователях

9 ноября 2026. После замеров полного набора пользователь выбрал сначала два пилота. Полный запуск остановлен во время initial validation, без завершённых эпох. Все дальнейшие вычисления локальны, на M3 Pro / MPS FP32, без CPU fallback.

**Итоговый scope: только сравнение большой 256 с оригинальной 256.** Обучение 1k отменено пользователем: короткая модель успела завершить 5 эпох (best 3), длинная остановлена внутри первой эпохи. Её last checkpoint сохранён локально, автоматическое продолжение отключено. Alpha и test для большой 1k не вычислялись. Попытка Watt отменена и [заархивирована](../archive/experiments/watt-2026-11-09/README.md); GPU-операция не создавалась.

## Протокол

- Повторно используем неизменные `yambda50m-pilot-audio` и `yambda50m-1k-audio`: 739 571 и 2 799 860 train-примеров, каталоги 114 125 и 244 194. Прежние OOT, target `played_ratio_pct > 50`, строгая прошлая история с исключением всей текущей timestamp-группы.
- Четыре независимых модели: 256/1k × окна 50/2. Trainable ID-векторы 64, hidden 256, 4 блока, 8 голов, FFN 1024, dropout 0.2. Входная и выходная проекции соединяют пространства 64 и 256. Encoder вне таблицы треков — около 3.2 млн параметров вместо 53.8 тыс.
- Короткая модель использует физическое окно 2; прежняя короткая модель маскировала начало окна 50. Видимые события совпадают, позиции и форма тензора отличаются. Это учитывается при интерпретации сравнения.
- Batch 256, общий BCE, 16 равномерных негативов, Adam 0.001 с betas (0.9, 0.98), clipping 5, seed 42 — как в прежних пилотах. Нет лимита эпох; patience 2 по полной model_valid NDCG@10, best checkpoint выбирается среди обученных эпох.
- Короткие benchmark-прогоны: 5 warmup + 2 × 50 training steps со случайными train-префиксами/негативами; отдельно warmup и 4 batch полного ранжирования каталога. Их веса не переносятся в основное обучение. Скорость не гарантирует число эпох до остановки.
- Модели обучаются последовательно. Атомарный `last.pt` сохраняет optimizer, NumPy/CPU/MPS RNG, порядок и позицию внутри эпохи; периодичность 5 000 шагов и после каждой эпохи. При прерывании используется `--resume` с прежним config/manifest/device.
- Для завершённой пары 256 alpha подбирается по полной model_valid NDCG@10: сетка 0, 0.1, ..., 1, при равенстве меньший alpha. Перед смешиванием — per-query z-score по кандидатам. Это согласование шкал, а не вероятностная калибровка. Selection фиксируется до новых test-оценок.
- Сравниваются отдельные модели и смеси на исходном test 256 с неизменными историями и кандидатами. Сравнение с прежними результатами выполняется по сохранённым per-event ranks, с парными пользовательскими интервалами; test не меняет конфигурации или alpha.
- Один seed, переиспользованный в предыдущих исследованиях test, изменение capacity и физического короткого окна ограничивают вывод о причинности и абсолютном потолке качества.

## Команды

```sh
PYTORCH_ENABLE_MPS_FALLBACK=0 .venv/bin/python scripts/run_sasrec.py benchmark --device mps --config configs/experiments/sasrec-256-large-long.json --output data/runs/sasrec-256-large-long/benchmark-mps.json
caffeinate -i .venv/bin/python scripts/run_sasrec_pairs.py
```

Для остальных benchmark меняются `256/1k` и `long/recent` в имени конфигурации и output. Orchestration по умолчанию обрабатывает только `256-large`, пропуская проверенные завершённые этапы. Отменённая 1k и полный набор автоматически не запускаются. Конфигурации: `configs/experiments/sasrec-{256,1k}-large-{long,recent}.json`; смешивание: `configs/experiments/sasrec-large-blend.json`. [Итоговое сравнение](../reports/experiments/sasrec-large.md).
